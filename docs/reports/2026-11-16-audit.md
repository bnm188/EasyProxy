## 0. 一句话结论

0.6.0 是一个"能装、能校验、能跑"的可用底座（真实内核接受配置、真实起服、代理端口实测 HTTP 200），但对照 16 项需求，**满足 3 项、部分满足 9 项、未满足 4 项**。核心缺口是：唯一 SSH 管理入口不存在（`easyproxy-manager.sh` 返回 404）、无缝切换完全没有、10 平台分流只有 3 个、10 个分组只是按名字自动分桶、发布资产可被同一版本号覆盖。同时实测到 4 个可复现的代码缺陷，其中 2 个会让功能直接不可用。

## 6. 缺陷清单（可复现）

### D1（P1）流量统计 tx 取错字段，总览曲线 tx 恒坏

- 位置：`package/easyproxy/files/usr/lib/easyproxy/traffic.sh:24` → `tx="$10"`
- 触发：面板总览页每 2 秒调 `traffic.sh` 采样（`app.js:196-240`）
- 实测（POSIX 语义）：`set -- br-lan 1234 … 5678 …; echo "$10"` → `br-lan0`。`$10` 被解析成 `${1}0`，不是第十个字段
- 影响：`tx` 变成 `"br-lan0"`，JSON 里 tx 是字符串，前端算速率得 `NaN`，发送速率曲线失效
- 为什么没被测出：测试只断言文件存在（`test-ipk-layout.sh:68`、`test-maintenance.sh:79`），没有对 `traffic.sh` 的输出做断言
- 修复：改 `${10}`；补一条"输出必须是合法 JSON、rx/tx 为整数"的断言

### D2（P1）面板错误分支调用未定义函数 `herrCard`

- 位置：`app.js:266`（`pageOverview` 里 status 读取失败时）
- 实测：静态扫描 `app.js` 全部函数定义与调用，唯一未定义标识符就是 `herrCard`（`errCard` 定义在 81 行）
- 触发：未安装、`/usr/sbin/easyproxy` 不可执行、status 返回失败
- 影响：抛 `ReferenceError`，本该显示的"无法读取状态"卡片不出现，页面直接空白/中断
- 为什么没被测出：JS 没有任何语法/引用检查，CI 也无 eslint/`node --check`
- 修复：改成 `errCard`；CI 增加 JS 静态检查

### D3（P1）面板可以把内核切成 dae，切完服务起不来

- 位置：`app.js:544-556`（内核下拉框保存 `main.engine`）；`easyproxy` 的 `run/start` 对非 sing-box 返回 2
- 触发：内核管理页选 `dae（开发中）` → 保存
- 实测：`config generate` 拒绝（"开发中"），`start` 退出码 2，透明抓包也不会 apply
- 影响：一次点击即可把可用服务变成不可用，且页面只提示"需重新生成配置并重启"，不阻止、不回退
- 修复：dae 选项置灰，或保存时校验 `ep_engine_stability`；切换后自动 regenerate + restart 并校验结果

### D4（P2）手工建 hysteria2/tuic 节点未带 `tls=1`，整份配置生成失败

- 位置：`config.sh:108-120`（两种类型把 `$tls` 拼在出站里，但 `tls` 来自 UCI 可选字段）
- 实测：UCI 里 `type=hysteria2`、有 `sni` 但无 `tls=1` → `Config generation failed: engine rejected … parse outbound[0]: TLS required`；加上 `tls=1` 后 `Engine validation: passed`
- 边界（反证）：分享链接导入路径会自动写 `tls=1`（`node.sh:218-219`），所以正常导入不受影响；受影响的是手写 UCI、第三方工具写节点、或只填了 sni 的用户
- 影响：一个节点写错，**全部节点**都用不了（生成直接失败，不降级）
- 修复：这两种类型强制 `tls=1`；或在 `config validate` 阶段给出字段级错误，而不是让内核 reject

### D5（P2）安装器在校验条件缺失时"跳过校验并继续安装"

- 位置：`scripts/install.sh:299-320`（`verify_download`）
- 触发：固件无 `sha256sum`、Release 没有 SHA256SUMS、或 SHA256SUMS 临时拉取失败 → 三者都 `return 0`
- 与声明冲突：文件头 15-19 行写"Nothing is installed before its sha256 has been checked"，Release 说明写"verifies every download against SHA256SUMS"；内核路径相反，缺 pinned sha 直接拒绝（603-604 行）
- 影响：面板包可能在未校验状态下被 opkg/apk 安装（虽然 ipk 还检查 ar magic，但内容完整性未验）
- 修复：改为硬失败，或提供显式 `--allow-unverified` 并在总结里标注"未校验"

### D6（P2）发布不可复现：同一版本号资产被反复覆盖

- 位置：`build.yml:171-225`；Release `immutable=false`
- 实测：tag `v0.6.0` → `68f9dddf`；HEAD `0f3c1c35` 领先 64 提交；Release 说明写 `built from 0f3c1c35`
- 影响：同一 URL 不同时间下载字节不同；外部 pin 的 sha 立刻失效；从 tag 源码构建得不到对应资产；直接违反"不覆盖旧版本"
- 修复：改 tag 触发构建（`on: push: tags: v*`），`main` 不再发 Release；每个版本独立 tag、独立不可变 Release；需要灰度时用 prerelease 通道

### D7（P2）升级体系缺四项

- 位置：`install.sh:851-958`
- 实测：只有内核有 `backup_kernel`/`restore_kernel`；面板包失败仅提示"旧包仍在"，无回滚动作；全仓库无 `df`、无磁盘空间检查、无固件版本兼容检查；升级前不备份 `/etc/config/easyproxy`
- 影响：不满足"升级前自动备份 / 失败自动回滚 / 兼容与磁盘检查"
- 修复：升级前 `tar` 备份配置 + `df` 预检 + 版本白名单；面板包保留旧 ipk 并在失败时重装

### D8（P2）CI 从未用真实内核校验配置，且"跳过"被计为通过

- 位置：`tests/test-routing.sh:230` → `ok "跳过真实 sing-box check（未提供二进制）"`；workflow 不安装 sing-box
- 影响：CI 的 471 项只能证明 JSON 形状与脚本逻辑；"配置能被内核接受"这一关键结论在 CI 里始终未验证（本次审计手工补测才成立）
- 修复：CI 下载 pinned sing-box 并导出 `EP_SING_BOX_BIN`；skip 计为 skip、不计数，或直接 fail

### D9（P2）ACL 把 `ubus file exec` 全量放开

- 位置：`luci-app-easyproxy.json` 的 `"ubus": { "file": ["exec","read","list"] }`
- 影响：持有该 ACL 的非 root LuCI 用户可借 `fs.exec` 执行任意命令（等价 root）。默认 root 管理员本来就全权，风险主要落在"委派账号"场景
- 修复：按路径收窄（`/usr/sbin/easyproxy`、`/usr/lib/easyproxy/traffic.sh` 等），去掉 `/bin/sh` 直调

### D10（P3）含节点凭据的配置文件是 0644

- 实测：`config generate` 产出 `-rw-r--r--`；全仓库无 `umask`/`chmod 600`
- 影响：本机其他用户可读到所有节点密码/UUID
- 修复：写配置前 `umask 077` 或 `chmod 600`

### D11（P3）自定义 `cache_file` 路径不建目录，内核启动即 FATAL

- 位置：`config.sh:217-218`（默认 `/etc/easyproxy/cache.db`）、写配置只 `mkdir -p` 配置自身目录
- 实测：把 `main.cache_file` 指到不存在的目录后 `sing-box run` → `FATAL start service: pre-start cache file: open …: no such file or directory`
- 反证（边界）：默认路径不触发——ipk 包内已建 `/etc/easyproxy/ruleset`，rootfs 安装写配置时也会创建 `/etc/easyproxy`；只有覆盖该 UCI 项时才踩
- 修复：写配置前 `mkdir -p "$(dirname "$(ep_cache_file)")"`

### D12（P3）文档声称支持 ssr://，实测不支持

- 位置：`README.md:226`（"understands ss://, ssr://, …"）；`node.sh:158-160` 默认分支
- 实测：`easyproxy node add 'ssr://…'` → `unsupported share link scheme: ssr`；README:16 的"8 share-link formats"实际是 7
- 修复：改文档，或补 ssr 解析（sing-box 无 shadowsocksr 出站，建议明确写"不支持"）

### D13（P3）`node test` 用 TCP 探测 QUIC 节点，必然误报

- 位置：`common.sh:270-320`（`ep_tcp_probe` 只做 TCP 连接）；节点类型含 hysteria2/tuic（UDP/QUIC）
- 影响：这两类节点永远显示 unreachable，用户会误删可用节点
- 修复：按协议分流（UDP 用 `nc -u` 不够，建议走内核 urltest 或 socks 拨测）；至少在 UI 标注"TCP 探测，UDP 协议结果不适用"

### D14（P3）"一键安装"不等于"装完可用"

- 实测：默认 `enabled=0`、`engine=none`、无节点；install.sh 结尾要求手工 add node → `config generate` → 启动（975-995 行）
- 影响：与"全自动安装、配置、启动"的要求有差距；新用户容易以为装坏了
- 修复：提供 `--node <link>` / 交互导入，或安装结束时明确打印"现在还不能用"的状态块

### D15（P3）唯一管理入口缺失

- 实测：`easyproxy-manager.sh` → HTTP 404，仓库无此文件
- 影响：需求 10 整条落空；现在是 4 条不同 URL 的命令，没有 9 项菜单
- 修复：新增根目录 `easyproxy-manager.sh`，菜单：安装/重装、升级、卸载、状态、诊断、内核管理、配置备份恢复、规则集更新、面板入口

### D16（P4）工程化细节

- CI 不产出测试报告文件（只有控制台日志）
- 无 shellcheck / 无 shfmt / 无 JS lint
- `install.sh` 999 行单文件，函数 60+，维护成本高
- 文档阶段口径不一致：README 写"Stage 6 current"，PROJECT-STATUS 写"Stage 7 已收口"
- `transparent.sh:117`、`app.js:338/510` 硬编码 `10.10.10.10`（站点特化值写进通用代码；功能上被 `10.0.0.0/8` 覆盖，属残留）

## 7. 哪些"只是看起来完成"

1. **10 个页面**：页面数量够，但订阅页只能一次性导入，内核页能把服务切死，总览错误分支是坏的。
2. **"dae 内核已安装"**：18 MB 二进制装进去了，适配器是空壳，`start` 直接拒绝——装 ≠ 能用。
3. **"10 个分组"**：是"按名字猜地区"的动态桶，节点名里没有地区关键词就全进 `other`；不能手动归组、不能选组。
4. **"测速"**：只测 TCP 握手一次，没有带宽/丢包/稳定性；UDP 协议结果还是错的。
5. **"平台分流"**：3 个内联域名表，不是 10 个平台，也没有卡片式管理。
6. **"无缝切换"**：完全没有，换节点必断流。
7. **"一键安装"**：装完是 `enabled=0 + 无节点`，还要三步手工操作。
8. **"正式 Release"**：同一版本号可变、可覆盖，tag 与资产不对应。
9. **"471 项测试全绿"**：CI 里真实内核校验被跳过；JS 与 `traffic.sh` 零覆盖，D1/D2 就是这么漏过去的。
10. **"透明抓包已实现"**：代码与单测都在，但没有一台真路由器的验收记录。

## 8. 安全与工程质量

| 项 | 结论 |
|---|---|
| 凭据保护 | 配置 0644（D10）；订阅 URL 不落盘（好）；`node add` 链接走 argv，会进 shell history 与 `ps`（低危） |
| 权限面 | ACL `ubus file exec` 全量放开（D9）；rpcd 写入仅限 `uci easyproxy` + `/etc/easyproxy/*`（合理） |
| 命令注入 | 全仓库无 `eval`；参数走 argv + UCI 字段，注入面小（好） |
| 校验链 | 下载 SHA256 + ar magic + 架构匹配 + 重试；但 D5 的"跳过"是缺口 |
| 抓包可逆性 | 独立 `table ip easyproxy` + 单条 ip rule，`remove`/`uninstall-clean` 可完整回滚，不碰 fw4（好） |
| 失败语义 | 配置生成失败不写坏配置（先写临时文件、内核 check 不过就删）；启动失败不 apply 抓包（好） |
| 可维护性 | 999 行安装器、63 行 dae 空壳、无 lint；文档与实现有 2 处偏差（D12、D16） |

**做得好的地方也要写清楚**：安全锁（国内直连 + fail_closed）是真的锁死而不是开关；抓包失败不会黑洞 LAN 的设计是对的；配置生成"先校验再落盘"是对的；安装器拒绝错架构/坏包、内核独立升级与回滚，这些比多数同类项目扎实。
