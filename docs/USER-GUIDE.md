# EasyProxy 面板使用手册

适用版本：`0.8.14`（含 `-30` 及后续）。入口 `http://<路由器IP>:8090`。

---

## 一、登录与初始化

| 场景 | 操作 |
|---|---|
| 首次打开 | 面板检测到没有密码文件时进入初始化页，设一次管理密码即完成 |
| 日常登录 | 输入管理密码，会话有效期 7 天，关闭浏览器重开一般仍在登录态 |
| 退出 | 右上角头像菜单 → 退出登录，服务端会同时删除该会话 token |

**忘记密码怎么找回**：本机 SSH 以 root 登录后删除密码文件，再打开面板即回到初始化页重新设置。

```sh
rm -f /etc/easyproxy/panel.pw
/etc/init.d/easyproxy-panel restart
```

改完直接刷新 `http://<路由器IP>:8090`，重新设一个密码即可，不影响节点、分流等配置。

## 二、六个一级页面

导航为「概览 / 分流 / 节点 / 网络 / 内核 / 系统」。窄屏（手机、平板竖屏）自动切换为底部 dock，逻辑一致。

### 1. 概览

看当前整体状态，不用点进各页就能判断“正不正常”。

- **实时运行状态**：内核是否 running、pid、运行时长、监听端口是否打开
- **硬件负载**：CPU 占用、内存占用、运行时长
- **流量**：实时上行 / 下行速率、累计流量
- **连接数**：当前活跃连接数量
- **内核状态**：当前引擎（mihomo / sing-box）、稳定性标记、启用节点数
- **站点连通性**：一组固定站点探测，显示状态码与耗时

> 数值为定时采样，切页后约 1～2 秒出第一组数据，出现「等待首次采样」属正常。

### 2. 分流

管理“哪类流量走哪个出口”。分三段展示，组内为空时卡片会变灰弱化，不占视觉焦点。

| 段 | 组 | 说明 |
|---|---|---|
| 业务组 | Netflix / YouTube / TikTok / AI / Disney+ / Google / Telegram / Apple / Games | 命中对应服务规则时使用本组出口 |
| 通用组 | 国外 / 其他 | 没命中具体服务时的兜底（国外 → 其他） |
| 特殊组 | 测速 / 国内 | 测速组只给速度测试用；国内组直连 |

单组卡片上的操作：

- **选择成员**：点节点名把该组切到指定节点或子组
- **测速本组**：对本组成员批量测延迟，结果按数值排序
- **删除成员 / 添加成员**：调整组成员；成员为空的组显示「未分配节点 · 兜底：其他」

页面顶部有搜索框（按组名或节点名过滤）、一键测速、刷新。底部还有两张只读卡片：全局出口、当前分流策略（只展示，不改）。

> 注意：`ip.net.coffee` 这类站点归属「测速」组，只能由测速组节点访问。换成其他组或换节点仍不通，属于设计而非故障。

### 3. 节点

- **订阅导入**在顶部订阅标签区，不在页面最底部
- 订阅链接填入后点「导入为节点」，导入结果进入节点池
- 节点列表支持按分组过滤、显示延迟、单个节点测速
- 节点开关（`节点开关` 列）可临时停用某个节点，不影响订阅本身的记录

### 4. 网络

三张卡：

1. **DNS 配置**：本地 DNS、远程 DNS、分流模式、fakeip 状态、缓存开关、规则集目录（多数只读，改动走系统页的运行参数）
2. **网络与端口**：监听端口、监听状态、本机出口检测
3. **连接与日志**：实时连接列表（可「断开」单个连接、按连接数排序）、运行日志（可「复制原文」、刷新）

### 5. 内核

- 显示当前内核、二进制路径、是否可用
- 可切换引擎（mihomo / sing-box）
- **重启**按钮重启当前内核进程

> 切到 sing-box 后若出现 `Enabled nodes: 1`，说明节点格式转换有缺口（见已知问题 KI-01），切回 mihomo 即恢复。

### 6. 系统

三张卡：

1. **管理密码**：填当前密码 + 新密码即可改，忘记密码时的兜底路径见第一节
2. **运行参数**：引擎、稳定/开发通道、中国策略、代理策略、失败关闭等运行选项
3. **运行自检**：一键跑诊断，输出版本、引擎、配置、规则集、运行时、监听、透明代理等检查项

右上角可切主题（深色 / 浅色），也可「退出登录」。

## 三、常见操作速查

| 想做的事 | 去哪 |
|---|---|
| 加一个机场订阅 | 节点 → 订阅导入 → 导入为节点 |
| 让 Netflix 走某节点 | 分流 → Netflix 组 → 选成员 |
| 某组全部节点测延迟 | 分流 → 对应组卡 → 测速本组 |
| 看当前哪条连接在跑 | 网络 → 连接与日志 |
| 换内核引擎 | 内核 → 切换 → 重启 |
| 改管理密码 | 系统 → 管理密码 |
| 面板打不开 | SSH `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8090`，非 200 则 `/etc/init.d/easyproxy-panel restart` |
| 判断整体是否健康 | 系统 → 运行自检 |

## 四、排障顺序

1. **面板打不开** → 先看 `8090` 是否监听，再重启 `easyproxy-panel`
2. **面板能开但没网** → 概览看内核是否 running、端口是否 open；内核页重启
3. **某个服务不通** → 分流页确认该服务所属组有可用成员、成员节点自身测速正常
4. **大面积不通** → 系统页运行自检，核对引擎、规则集、透明代理状态
